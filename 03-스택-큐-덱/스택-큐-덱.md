## 스택 · 큐 · 덱

셋 다 [리스트](../02-배열과-리스트/배열과-리스트.md)처럼 순서대로 데이터를 담지만, **넣고 빼는 위치를 양 끝으로 제한**한 자료구조다.
제한을 걸었기 때문에 탐색이나 요소 이동이 필요 없고, 그래서 모든 연산이 O(1)로 유지된다.
자바에서는 셋 다 `Deque` 인터페이스와 그 구현체 `ArrayDeque`로 처리할 수 있다.

### 스택
+ 후입선출 (LIFO, Last In First Out) 방식으로 동작하는 자료구조
    - 스택은 맨 위에서만 삽입/삭제가 일어난다
    - 인덱스로 맨 끝 요소에 O(1)로 접근할 수 있는 자료구조가 있다
        + `LinkedList`
            - 양쪽 끝 O(1) : 스택에는 양쪽 끝이 필요없다
        + `ArrayList`
            - 한쪽 끝 O(1) : 메모리가 연속적
        + 그럼 `ArrayList`가 스택에 더 유리할까?
            - `get(index)`, `add(2, element)`와 같은 스택에서 사용할 수 없는 연산도 존재
            - 원형 버퍼를 사용하여 공간을 더 효율적으로 사용할 수 있는 `ArrayDeque`가 존재

                ```
                // ArrayList
                [_][_][3][4][5][_]  // 일반 배열을 앞부터 제거하면 앞 공간이 낭비된다

                // ArrayDeque
                index: [0][1][2][3][4]
                data:  [_][1][2][3][_]  // 1이 빠지면 시작점이 바뀌니 head가 이동
                ```
+ 접시쌓기, 실행 취소(Undo) 등의 기능구현에 사용
+ 자바에서는 `java.util.Stack`보다 `Deque<E> stack = new ArrayDeque<>()`를 쓴다
    - `Stack`은 `Vector`를 상속한 레거시 클래스라 모든 메서드에 동기화 비용이 붙는다
    - `Stack`은 인덱스 접근이 열려 있어 스택으로 쓰겠다는 의도가 드러나지 않는다

|연산|설명|시간 복잡도|
|---|---|---|
|`push(e)`|스택 맨 위에 요소 추가|O(1)|
|`pop()`|스택 맨 위의 요소 제거|O(1)|
|`peek()`|스택 맨 위의 요소 확인(제거 X)|O(1)|
|`isEmpty()`|스택이 비어있는지 확인|O(1)|

### 큐
+ 선입선출 (FIFO, First In First Out) 방식으로 동작하는 자료구조
+ 프린터 대기열, 네트워크 패킷 처리 등에 사용
+ 자바에서는 `Queue<E> queue = new ArrayDeque<>()`로 사용한다
    - `LinkedList`도 `Queue`를 구현하지만 노드마다 객체를 만들어 `ArrayDeque`보다 느리다

|연산|설명|시간 복잡도|
|---|---|---|
|`offer(e)`|큐의 맨 뒤에 요소 추가 (enqueue)|O(1)|
|`poll()`|큐의 맨 앞 요소 제거 (dequeue)|O(1)|
|`peek()`|큐의 맨 앞 요소 확인(제거 X)|O(1)|
|`isEmpty()`|큐가 비어있는지 확인|O(1)|

### 덱
+ Double-ended Queue
+ 양쪽에서 삽입과 삭제가 가능한 큐
+ 스택과 큐의 기능 모두 포함
+ 슬라이딩 윈도우, 회문 검사처럼 **양 끝을 동시에 다뤄야 하는 문제**에 쓴다

|연산|설명|시간 복잡도|
|---|---|---|
|`addFirst(e)`|앞에 요소 추가|O(1)|
|`addLast(e)`|뒤에 요소 추가|O(1)|
|`pollFirst()`|앞에서 요소 제거|O(1)|
|`pollLast()`|뒤에서 요소 제거|O(1)|
|`peekFirst()` / `peekLast()`|양 끝 요소 확인(제거 X)|O(1)|
|`isEmpty()`|덱이 비어있는지 확인|O(1)|

+ `ArrayDeque`의 `push()` / `pop()`은 앞쪽(`addFirst` / `pollFirst`)에 연결된다
    - 스택으로 쓸 때와 큐로 쓸 때 **꺼내는 끝이 달라지므로** 메서드를 섞어 쓰지 않는다
