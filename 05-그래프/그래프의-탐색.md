## 그래프의 탐색

너비 우선 탐색(BFS)과 깊이 우선 탐색(DFS)은 그래프(또는 트리)에서 **모든 노드를 탐색**하는 대표적인 알고리즘이다.
BFS는 가까운 노드부터 탐색하고, DFS는 한쪽으로 끝까지 탐색한 뒤 되돌아온다.

둘은 **"다음에 어디를 볼지 어디에 담아두느냐"** 만 다르다.
큐에 담으면 먼저 넣은 것이 먼저 나와 가까운 곳부터 퍼지고(BFS), 스택에 담으면 마지막에 넣은 것이 먼저 나와 한 줄기로 파고든다(DFS).
**나머지 코드는 거의 같다.**

### 탐색 전에 정해두는 것
+ **그래프 표현** : 이 문서는 전부 [인접 리스트](그래프.md) 기준이다. 이웃만 골라 볼 수 있어 탐색에 유리하다
+ **`visited` 배열** : 트리와 달리 그래프는 **사이클이 있을 수 있으므로 필수**다. 없으면 무한 루프에 빠진다
+ **시작 정점** : 그래프에는 루트가 없다. 아무 정점에서나 시작할 수 있고, 시작점이 바뀌면 결과도 바뀐다

```
visited 없이 순환 그래프를 돌면

  (1)───(2)        1 → 2 → 3 → 1 → 2 → 3 → ... 영원히 끝나지 않는다
    ╲    │
     ╲  (3)
```

예제는 아래 그래프를 기준으로 한다. 방향 그래프이고, 정점 번호는 1번부터다.

```
       (1)          ← 레벨 0
      ╱   ╲
    (2)   (3)       ← 레벨 1
     │     │
    (4)   (5)       ← 레벨 2

 BFS : 레벨 순으로 훑는다     1 → 2 3 → 4 5
 DFS : 한 줄기를 끝까지 판다   1 → 2 → 4 ↩ 3 → 5
```

```java
import java.util.*;

int V = 5;
List<List<Integer>> graph = new ArrayList<>();
for (int i = 0; i <= V; i++) graph.add(new ArrayList<>());  // 1번부터 쓰려고 V+1개

graph.get(1).add(2);   graph.get(1).add(3);
graph.get(2).add(4);
graph.get(3).add(5);
```

> 무방향 그래프라면 `graph.get(2).add(1)`처럼 **양쪽에 모두 넣어야** 한다.

### 너비 우선 탐색 (Breadth-First Search)
+ 탐색을 시작할 노드를 큐(Queue)에 넣고 바로 방문 처리
    - 큐에서 노드를 하나 꺼냄
    - 꺼낸 노드의 인접 노드들 중
    - 방문하지 않은 노드들을 큐에 추가하면서 방문 처리함
    - 큐가 빌 때까지 이 과정을 반복함
+ 시작점에서 **거리가 같은 정점들을 한 겹씩** 방문한다. 그래서 "너비 우선"이다

```
큐: [1]           방문 처리: 1
  1 꺼냄 → 2, 3 넣음
큐: [2, 3]        방문 처리: 1 2 3
  2 꺼냄 → 4 넣음
큐: [3, 4]        방문 처리: 1 2 3 4
  3 꺼냄 → 5 넣음
큐: [4, 5]        방문 처리: 1 2 3 4 5
  4 꺼냄 → 넣을 것 없음
큐: [5]
  5 꺼냄 → 큐가 비어 종료

방문 순서: 1 2 3 4 5
```

```java
import java.util.*;

static void bfs(List<List<Integer>> graph, int start) {
    boolean[] visited = new boolean[graph.size()];
    Queue<Integer> queue = new ArrayDeque<>();

    queue.offer(start);
    visited[start] = true;          // 큐에 넣는 순간 방문 처리한다

    while (!queue.isEmpty()) {
        int node = queue.poll();
        System.out.print(node + " ");

        for (int next : graph.get(node)) {
            if (!visited[next]) {
                visited[next] = true;
                queue.offer(next);
            }
        }
    }
}

bfs(graph, 1);   // 1 2 3 4 5
```

+ 큐는 `LinkedList`가 아니라 **`ArrayDeque`** 를 쓴다 ([스택 · 큐 · 덱](../03-스택-큐-덱/스택-큐-덱.md))
+ **방문 처리는 꺼낼 때가 아니라 큐에 넣을 때 한다**
    - 꺼낼 때 처리하면 같은 정점이 큐에 여러 번 들어간다. 정점 A의 이웃이면서 B의 이웃이기도 한 정점은 두 번 삽입된다
    - 결과는 맞을 수 있지만 큐가 부풀어 최악에는 O(E)까지 커진다

```
❌ 꺼낼 때 방문 처리          ✅ 넣을 때 방문 처리
   큐: [2, 3]                  큐: [2, 3]
   2 꺼냄 → 4 넣음             2 꺼냄 → 4 넣음(+방문 처리)
   3 꺼냄 → 4 또 넣음          3 꺼냄 → 4는 이미 방문 → 넣지 않음
   큐: [4, 4]  ← 중복          큐: [4]
```

### 깊이 우선 탐색 (Depth-First Search)
+ 탐색을 시작할 노드를 스택(Stack) 또는 재귀로 방문 처리함
    - 현재 노드의 인접 노드들을 순서대로 확인함
    - 방문하지 않은 노드를 재귀 호출로 즉시 방문 처리함
    - 더 이상 방문할 노드가 없으면 이전 노드로 되돌아가 탐색을 이어감
+ 되돌아가는 동작을 **백트래킹(backtracking)** 이라고 한다

```
1 방문 → 이웃 2로 내려감
  2 방문 → 이웃 4로 내려감
    4 방문 → 갈 곳 없음        ↩ 2로 복귀
  2 → 남은 이웃 없음           ↩ 1로 복귀
1 → 다음 이웃 3으로 내려감
  3 방문 → 이웃 5로 내려감
    5 방문 → 갈 곳 없음        ↩ 종료

방문 순서: 1 2 4 3 5
```

#### 재귀로 구현

```java
static void dfs(List<List<Integer>> graph, int node, boolean[] visited) {
    visited[node] = true;
    System.out.print(node + " ");

    for (int next : graph.get(node)) {
        if (!visited[next]) {
            dfs(graph, next, visited);
        }
    }
}

boolean[] visited = new boolean[graph.size()];
dfs(graph, 1, visited);   // 1 2 4 3 5
```

+ 코드가 짧고 직관적이라 **기본은 재귀**다
+ 대신 **재귀 깊이가 곧 스택 깊이**다. 자바 기본 스택으로는 대략 **1만 회 근처에서 `StackOverflowError`** 가 난다
    - 정점 10만 개가 일자로 이어진 그래프라면 재귀 DFS는 터진다

```java
// 스택 크기를 64MB로 키워서 실행하는 우회법
new Thread(null, () -> dfs(graph, 1, new boolean[graph.size()]), "dfs", 64 * 1024 * 1024).start();
```

#### 스택으로 구현

```java
static void dfsIterative(List<List<Integer>> graph, int start) {
    boolean[] visited = new boolean[graph.size()];
    Deque<Integer> stack = new ArrayDeque<>();
    stack.push(start);

    while (!stack.isEmpty()) {
        int node = stack.pop();
        if (visited[node]) continue;    // 스택 버전은 꺼낼 때 방문 처리한다
        visited[node] = true;
        System.out.print(node + " ");

        // 재귀와 같은 순서로 돌리려면 이웃을 역순으로 넣는다
        List<Integer> nexts = graph.get(node);
        for (int i = nexts.size() - 1; i >= 0; i--) {
            if (!visited[nexts.get(i)]) stack.push(nexts.get(i));
        }
    }
}
```

+ 깊이 제한이 없어 **정점이 아주 많을 때 안전**하다
+ **BFS와 방문 처리 시점이 반대**인 점에 주의한다
    - BFS는 넣을 때, 스택 DFS는 **꺼낼 때** 처리한다. 넣을 때 처리하면 재귀와 방문 순서가 달라진다
    - 대신 같은 정점이 스택에 중복으로 들어갈 수 있어 `if (visited[node]) continue;` 가드가 필요하다
+ 이웃을 **역순으로 넣어야** 재귀와 같은 순서가 나온다. 스택은 마지막에 넣은 것이 먼저 나오기 때문이다

### DFS와 BFS 비교

|기준|BFS|DFS|
|---|---|---|
|사용하는 자료구조|큐 (`ArrayDeque`)|스택 또는 재귀|
|탐색 순서|가까운 정점부터 (레벨 순)|한 방향으로 끝까지 간 뒤 되돌아옴|
|시간 복잡도|O(V + E)|O(V + E)|
|공간 복잡도|O(V) — 큐에 한 레벨이 통째로 들어간다|O(V) — 스택 깊이 = 경로 길이|
|불리한 그래프|**넓은** 그래프 (큐가 커짐)|**깊은** 그래프 (`StackOverflowError`)|
|방문 처리 시점|큐에 **넣을 때**|재귀는 들어갈 때, 스택은 **꺼낼 때**|
|잘하는 일|**비가중 최단 경로**, 거리 · 레벨 계산|경로 탐색, 사이클 판별, 백트래킹, 위상 정렬|

+ 고르는 기준
    - **"최소 몇 번 만에 도달하는가"** 를 물으면 → BFS. 처음 도달한 순간이 곧 최단이다
    - **"가능한 모든 경우를 만들어봐야 한다"** 면 → DFS (백트래킹)
    - **그냥 전부 훑기만 하면 된다**면 → 아무거나. 보통 DFS 재귀가 코드가 짧다
+ 시간 복잡도가 같은 이유는 둘 다 **모든 정점을 한 번, 모든 간선을 한 번씩** 보기 때문이다
    - 인접 리스트면 O(V + E), **인접 행렬이면 O(V²)** 다. 표현 방식이 탐색 비용을 결정한다

### 놓치기 쉬운 것

#### 방문 순서는 인접 리스트의 순서에 달렸다
+ 같은 그래프라도 **간선을 넣은 순서**가 다르면 방문 순서가 달라진다
+ `graph.get(1).add(3)`을 먼저 했다면 DFS는 `1 3 5 2 4`가 된다
+ "정답 순서"가 정해진 문제라면 **인접 리스트를 정렬**하고 시작한다

```java
for (List<Integer> list : graph) Collections.sort(list);   // 번호가 작은 이웃부터
```

#### 비연결 그래프는 한 번의 탐색으로 다 못 훑는다
+ 시작 정점에서 도달할 수 없는 정점은 영원히 방문되지 않는다
+ 전부 훑으려면 **모든 정점을 시작점으로 한 번씩** 시도한다

```java
boolean[] visited = new boolean[V + 1];
for (int i = 1; i <= V; i++) {
    if (!visited[i]) {
        dfs(graph, i, visited);   // 연결 요소 하나를 통째로 훑는다
    }
}
```

#### BFS의 최단 경로는 가중치가 없을 때만 성립한다
+ BFS가 최단을 보장하는 이유는 **모든 간선의 비용이 1로 같기** 때문이다
+ 간선마다 가중치가 다르면 "간선 수가 적은 경로"가 "비용이 싼 경로"가 아니다 → **다익스트라**를 써야 한다

### 정리
+ BFS와 DFS는 **다음에 볼 정점을 큐에 담느냐 스택에 담느냐**만 다르다. 나머지 골격은 같다
+ 그래프는 사이클이 있을 수 있으므로 **`visited`가 필수**다. 트리 순회와 갈라지는 지점이 여기다
+ 방문 처리 시점이 다르다 — **BFS는 넣을 때, 스택 DFS는 꺼낼 때**
+ 둘 다 인접 리스트 기준 **O(V + E)**, 인접 행렬 기준 O(V²)
+ 넓은 그래프는 BFS의 큐가, 깊은 그래프는 DFS의 스택이 부담이다
+ **비가중 최단 경로가 필요하면 BFS**, 모든 경우를 만들어봐야 하면 DFS
