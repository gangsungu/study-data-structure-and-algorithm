## 그래프

정점(Vertex)과 간선(Edge)으로 **연결 관계 자체를 표현**하는 자료구조다.
배열·리스트가 "순서"를, 트리가 "계층"을 표현한다면 그래프는 **N : N 관계**를 표현한다.
지하철 노선도, 친구 관계, 웹 페이지 링크, 작업 선후 관계처럼 **"무엇이 무엇과 이어져 있는가"** 가 데이터의 본질일 때 쓴다.
자바에는 표준 그래프 클래스가 없어서 **배열이나 `List` · `Map`으로 직접 만든다.**

### 그래프
+ 정점(Vertex, Node)과 간선(Edge)으로 이루어진 자료구조
    - 정점: 데이터가 저장되는 지점
    - 간선: 정점 간의 연결을 나타내는 선
+ 객체 간의 연결 관계를 표현하는 데 유용
+ 네트워크, 소셜 미디어, 지도(길 찾기) 등 다양한 분야에서 사용됨
+ 보통 **V = 정점 개수, E = 간선 개수**로 쓰고, 그래프의 복잡도는 이 둘로 표기한다

```
   (0)───(1)      정점 V = {0, 1, 2, 3}
    │     │       간선 E = {(0,1), (0,2), (1,3), (2,3)}
    │     │
   (2)───(3)      V = 4, E = 4
```

#### 용어

|용어|의미|
|---|---|
|인접(Adjacent)|두 정점이 간선으로 직접 연결된 상태|
|차수(Degree)|한 정점에 연결된 간선의 수. 방향 그래프에서는 진입 차수(in-degree)와 진출 차수(out-degree)로 나눈다|
|경로(Path)|한 정점에서 다른 정점까지 간선을 따라 이어지는 정점의 나열|
|사이클(Cycle)|시작한 정점으로 다시 돌아오는 경로|
|연결 요소(Connected Component)|서로 도달 가능한 정점들의 덩어리|
|자기 간선(Self-loop)|자기 자신으로 돌아오는 간선|
|다중 간선|같은 두 정점을 잇는 간선이 2개 이상인 경우|
|단순 그래프|자기 간선도 다중 간선도 없는 그래프. 보통 "그래프"라 하면 이것을 말한다|

+ 무방향 그래프에서 **모든 정점 차수의 합 = 간선 수 × 2** 다 (간선 하나가 양쪽 차수를 1씩 올린다)
+ 정점이 V개인 단순 그래프의 **최대 간선 수**
    - 무방향 : `V(V-1)/2`, 방향 : `V(V-1)`
    - 즉 **E는 최대 O(V²)** 이고, 이 사실이 아래 구현 방식을 고르는 기준이 된다

### 그래프의 종류
+ **방향 그래프 (Directed Graph)**
    - 간선에 방향이 있음. `A → B`가 있다고 `B → A`가 있는 것은 아니다
    - 인스타그램 팔로우, 웹 페이지 링크, 작업 선후 관계
+ **무방향 그래프 (Undirected Graph)**
    - 간선에 방향이 없음, 양 방향으로 이동 가능
    - 페이스북 친구 관계, 양방향 도로망

    ```
    무방향                방향
     (A)───(B)          (A)──▶(B)
     A→B ✅  B→A ✅      A→B ✅  B→A ❌
    ```

+ **가중 그래프 (Weighted Graph)**
    - 간선에 가중치(Weight)가 있음
    - 길 찾기(예: 네비게이션), 네트워크 연결 비용 계산 등에 사용됨
    - 가중치는 거리일 수도 있고 시간 · 비용 · 용량일 수도 있다. **가중치가 없으면 모든 간선의 비용이 1인 것과 같다**
+ **비순환 그래프 (Acyclic Graph)**
    - 사이클이 없는 그래프. 그중 **방향 비순환 그래프(DAG)** 가 특히 중요하다
    - 선수 과목, 빌드 의존성, 작업 스케줄링 → **위상 정렬을 쓸 수 있는 유일한 그래프**
+ **연결 그래프 / 비연결 그래프**
    - 모든 정점 쌍 사이에 경로가 있으면 연결 그래프
    - 비연결 그래프는 연결 요소가 여러 개다. 그래서 **전체를 훑으려면 정점마다 탐색을 시도**해야 한다
+ **완전 그래프 (Complete Graph)**
    - 모든 정점 쌍이 간선으로 이어진 그래프. 간선 수가 최대다
+ **희소 그래프 / 밀집 그래프**
    - E가 V에 가까우면 희소(sparse), V²에 가까우면 밀집(dense)
    - **현실 문제 대부분은 희소하다.** 지하철역 하나가 전국 모든 역과 직접 이어지지는 않는다

#### 트리와의 관계
+ 트리는 **사이클이 없는 연결 그래프**다. 즉 트리는 그래프의 특수한 경우다
+ 정점이 V개인 트리의 간선은 정확히 **V - 1개**다. 하나라도 더 있으면 사이클이 생긴다
+ 그래프에는 루트 · 부모 · 자식 개념이 없고 시작 정점을 아무 데나 잡을 수 있다

### 그래프의 구현
자바에는 표준 그래프 클래스가 없다. 아래 세 가지 중 하나를 **직접 골라서 만든다.**
설명은 모두 같은 그래프를 기준으로 한다.

```
        2
   (0)─────(1)          간선 4개, 모두 가중치가 있는 무방향 그래프
    │       │           0번과 3번은 직접 연결되어 있지 않다
   4│       │3
    │       │
   (2)─────(3)
        1
```

+ 인접 행렬(Adjacency Matrix)
    - 2차원 배열을 사용하여 정점 간 연결 여부를 저장
    - 두 정점의 **연결 여부와 가중치를 O(1)에 조회** 가능
    - 메모리 사용량이 많음 (O(V²), V=정점 개수)
    - 무방향 그래프의 인접 행렬은 **대각선을 기준으로 대칭**이다

    ```
          0    1    2    3
     0 [  0,   2,   4,  INF ]
     1 [  2,   0,  INF,  3  ]     INF = 연결되지 않음
     2 [  4,  INF,  0,   1  ]     대각선(자기 자신)은 0
     3 [ INF,  3,   1,   0  ]
    ```

    ```java
    import java.util.Arrays;

    final int INF = 100_000_000;   // 연결되지 않음
    int V = 4;

    int[][] graph = new int[V][V];
    for (int[] row : graph) Arrays.fill(row, INF);
    for (int i = 0; i < V; i++) graph[i][i] = 0;

    // 무방향 그래프라 양쪽을 모두 채운다
    graph[0][1] = graph[1][0] = 2;
    graph[0][2] = graph[2][0] = 4;
    graph[1][3] = graph[3][1] = 3;
    graph[2][3] = graph[3][2] = 1;

    graph[1][3];   // 3   - 두 정점의 연결 확인은 O(1)
    graph[0][3];   // INF - 연결되어 있지 않다

    // 0번 정점의 이웃 전부 찾기 - 한 줄을 다 훑어야 하므로 O(V)
    for (int next = 0; next < V; next++) {
        if (next != 0 && graph[0][next] != INF) {
            System.out.println(next + " (가중치 " + graph[0][next] + ")");
        }
    }
    ```

    > `INF`를 `Integer.MAX_VALUE`로 두면 `INF + 가중치`에서 **오버플로가 나서 음수가 된다.**
    > 최단 경로처럼 거리를 더하는 알고리즘에서는 `100_000_000`처럼 "더해도 안전한 큰 값"을 쓴다.

+ 인접 리스트 (Adjacency List)
    - 각 정점이 연결된 정점들을 리스트로 저장
    - 메모리를 적게 사용 (O(V + E), V=정점 수, E=간선 수)
    - 특정 정점의 모든 연결을 탐색할 때 유리함 (**차수만큼만** 돌면 된다)

    ```
     0 → (1, 2), (2, 4)
     1 → (0, 2), (3, 3)          (연결된 정점, 가중치)
     2 → (0, 4), (3, 1)
     3 → (1, 3), (2, 1)
    ```

    ```java
    import java.util.ArrayList;
    import java.util.List;

    int V = 4;
    List<List<int[]>> graph = new ArrayList<>();
    for (int i = 0; i < V; i++) graph.add(new ArrayList<>());

    // {연결된 정점, 가중치} - 무방향이므로 양쪽에 넣는다
    graph.get(0).add(new int[]{1, 2});   graph.get(1).add(new int[]{0, 2});
    graph.get(0).add(new int[]{2, 4});   graph.get(2).add(new int[]{0, 4});
    graph.get(1).add(new int[]{3, 3});   graph.get(3).add(new int[]{1, 3});
    graph.get(2).add(new int[]{3, 1});   graph.get(3).add(new int[]{2, 1});

    // 0번 정점의 이웃만 순회 - 연결된 만큼만 돌므로 O(차수)
    for (int[] e : graph.get(0)) {
        System.out.println(e[0] + " (가중치 " + e[1] + ")");
    }

    // 0번과 3번이 연결됐는지 확인 - 리스트를 훑어야 해서 O(차수)
    boolean connected = graph.get(0).stream().anyMatch(e -> e[0] == 3);  // false
    ```

    - `int[]` 대신 `record`를 쓰면 `e[0]`, `e[1]`이 무슨 뜻인지 이름으로 드러난다

    ```java
    record Edge(int to, int weight) {}

    List<List<Edge>> graph = new ArrayList<>();
    graph.get(0).add(new Edge(1, 2));

    for (Edge e : graph.get(0)) {
        System.out.println(e.to() + " (가중치 " + e.weight() + ")");
    }
    ```

    - 정점 이름이 숫자가 아니라면 `Map<String, List<Edge>>`처럼 [해시 테이블](../04-해시-테이블/해시-테이블.md)을 쓴다

+ 간선 리스트 (Edge List)
    - 정점이 아니라 **간선 자체를 `{시작, 끝, 가중치}` 목록**으로 들고 있는 방식
    - 공간은 O(E)로 가장 작지만, "0번의 이웃"을 물으면 전부 훑어야 해서 탐색에는 불리하다
    - **간선을 정렬하거나 전부 한 번씩 훑는 알고리즘**(크루스칼 MST, 벨만-포드)에서 쓴다

    ```java
    import java.util.Arrays;

    // {시작, 끝, 가중치}
    int[][] edges = {
        {0, 1, 2},
        {0, 2, 4},
        {1, 3, 3},
        {2, 3, 1}
    };

    // 가중치 기준 정렬이 한 줄이다 → 크루스칼 알고리즘
    Arrays.sort(edges, (a, b) -> a[2] - b[2]);
    ```

#### 인접 행렬 vs 인접 리스트 vs 간선 리스트

|기준|인접 행렬|인접 리스트|간선 리스트|
|---|---|---|---|
|공간 복잡도|O(V²)|O(V + E)|O(E)|
|두 정점의 연결 확인|**O(1)**|O(차수)|O(E)|
|한 정점의 이웃 전체 순회|O(V)|**O(차수)**|O(E)|
|간선 추가|O(1)|O(1)|O(1)|
|간선 삭제|**O(1)**|O(차수)|O(E)|
|전체 순회 (탐색)|O(V²)|**O(V + E)**|O(E)|
|유리한 경우|밀집 그래프, 연결 여부를 자주 묻는 경우|희소 그래프 (**대부분의 경우**)|간선을 정렬 · 순회하는 알고리즘|

+ 고르는 기준은 하나다 — **E가 V²에 가까운가(밀집), V에 가까운가(희소)**
    - 정점이 10,000개면 인접 행렬은 1억 칸이다. `int`면 약 400MB라 **아예 쓸 수 없다**
    - 같은 조건에서 인접 리스트는 실제 간선 수만큼만 쓴다 → **기본값은 인접 리스트**
+ 플로이드-워셜처럼 **모든 정점 쌍의 거리**를 다루는 알고리즘은 인접 행렬이 자연스럽다
+ 이 선택이 곧 탐색 비용을 결정한다. 같은 DFS · BFS라도 **인접 리스트면 O(V + E), 인접 행렬이면 O(V²)** 다

#### 자주 하는 실수
+ **무방향 그래프인데 한쪽만 등록한다.** 간선 하나를 넣을 때 `A → B`와 `B → A`를 모두 넣어야 한다
+ **정점 번호가 1번부터 시작하는데 배열을 V 크기로 잡는다.** `V + 1` 크기로 잡고 0번을 버리는 편이 인덱스 실수가 없다
+ **가중치 0인 간선과 "연결 없음"을 둘 다 0으로 표현한다.** 인접 행렬에서는 연결 없음을 `INF`나 `-1`로 구분해야 한다

### 그래프 탐색
+ 그래프에 담은 데이터를 쓰려면 결국 **정점을 따라 돌아다녀야** 한다. 기본 전략은 두 가지다
    - **DFS(깊이 우선 탐색)** : 한 방향으로 끝까지 가보고 막히면 되돌아온다. **스택**(또는 재귀)을 쓴다
    - **BFS(너비 우선 탐색)** : 가까운 정점부터 물결처럼 퍼진다. **큐**를 쓰며, **비가중 그래프의 최단 경로**를 구할 때 쓴다
+ 트리와 달리 그래프는 **사이클이 있을 수 있으므로 `visited` 배열이 필수**다. 없으면 무한 루프에 빠진다
+ 둘 다 모든 정점과 간선을 한 번씩 보므로 **인접 리스트 기준 O(V + E)**, 인접 행렬 기준 O(V²)

> DFS · BFS의 동작 방식과 구현은 [그래프의 탐색](그래프의-탐색.md), 최단 경로 · 사이클 판별 같은 활용은 [탐색의 활용](탐색의-활용.md) 문서에서 다룬다.

### 그래프 알고리즘 지도

|풀려는 문제|알고리즘|주로 쓰는 표현|
|---|---|---|
|비가중 그래프의 최단 경로|BFS|인접 리스트|
|가중치 최단 경로 (음수 없음)|다익스트라|인접 리스트 + 우선순위 큐|
|음수 가중치가 있는 최단 경로|벨만-포드|간선 리스트|
|모든 정점 쌍의 최단 경로|플로이드-워셜|인접 행렬|
|최소 신장 트리(MST)|크루스칼 / 프림|간선 리스트 / 인접 리스트|
|작업 선후 순서 정하기|위상 정렬|인접 리스트 (DAG에서만)|
|연결 요소 · 사이클 판별|DFS, 유니온-파인드|인접 리스트|

+ 각 알고리즘이 **어떤 표현을 요구하는지**가 곧 구현 방식을 고르는 실전 기준이다

### 정리
+ 그래프는 순서도 계층도 아닌 **"관계 그 자체"** 를 표현하는 자료구조다
+ 방향 · 가중치 · 사이클 유무에 따라 성격이 완전히 달라지고, 쓸 수 있는 알고리즘도 달라진다
+ 자바에 표준 구현이 없으므로 **인접 행렬 · 인접 리스트 · 간선 리스트 중 하나를 직접 고른다**
+ 판단 기준은 **E가 V²에 가까운가(밀집 → 행렬), V에 가까운가(희소 → 리스트)** 하나다. 현실 대부분은 희소해서 인접 리스트가 기본값이다
+ 트리는 사이클 없는 연결 그래프, 즉 **그래프의 특수한 경우**다
