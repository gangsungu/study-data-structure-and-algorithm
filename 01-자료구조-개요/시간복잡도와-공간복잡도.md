## 시간복잡도와 공간복잡도

복잡도는 코드가 **몇 초 걸리는지**가 아니라 **입력이 커질 때 얼마나 빨리 나빠지는지**를 재는 자다.
그래서 상수와 낮은 차수 항은 버리고, 보통 최악의 경우를 기준으로 본다.
[자료구조란](자료구조란.md)에서 나눈 자료구조들을 고를 때 실제 판단 기준이 되는 값이다.

### 시간 복잡도
+ 알고리즘이 실행되는데 걸리는 시간을 입력 크기(n)에 따라 분석한 것
    - n이 커질수록 연산 횟수가 얼마나 늘어나는가
    - 간단한 판단 기준
        + 고정된 횟수로 끝나는가 > O(1)
        + n에 비례해서 늘어나는가 > O(n)
        + n<sup>2</sup>에 비례해서 늘어나는가 > O(n<sup>2</sup>)
            ```
            // ArrayList 앞에서 제거
            [1][2][3][4][5]  → 요소 5개, 이동 4번
            [1][2]...[100]   → 요소 100개, 이동 99번

            n이 커질수록 이동 횟수도 같이 커진다
            → O(n) ✅

            // ArrayDeque 앞에서 제거
            head 포인터 하나만 이동
            요소가 5개든 100개든 딱 1번
            → O(1) ✅
            ```
+ 입력이 커질수록 얼마나 더 느려지는지 예측할 수 있게 도와줌

#### 빅-오 표기법 (Big-O)
+ 최악의 경우를 기준으로 연산 횟수를 표현
+ 안전한 성능 보장이 필요하기 때문에 최악을 기준으로 잡는다
    - O(1)
        + 상수 시간
        + 배열에서 인덱스로 접근
    - O(log n)
        + 로그 시간
        + 이진 탐색
        + 로그 log<sub>2</sub>(n)
    - O(n)
        + 선형 시간
        + 배열에서 특정 원소 찾기
    - O(n log n)
        + 로그 선형 시간
        + 퀵 정렬, 병합 정렬
        + O(n) 반복 * log<sub>2</sub>
    - O(n<sup>2</sup>)
        + 이차 시간
        + 버블 정렬, 선택 정렬
        + n(n+1)/2 (가우스 공식)
    - O(2<sup>n</sup>)
        + 지수 시간
        + 피보나치 수열의 재귀적 계산
    - O(n!)
        + 팩토리얼 시간
        + 모든 순열을 만들어보는 완전 탐색 (외판원 문제)
+ 증가 속도 순서
    - O(1) < O(log n) < O(n) < O(n log n) < O(n<sup>2</sup>) < O(2<sup>n</sup>) < O(n!)
+ 로그의 밑은 생략한다
    - log<sub>2</sub>(n)과 log<sub>10</sub>(n)은 밑 변환 공식에 따라 상수배 차이일 뿐이라 증가율이 같다
    - 자료구조에서는 보통 `절반씩` 줄여나가므로 밑이 2다

|입력 크기(n)|O(1)|O(log n)|O(n)|O(n log n)|O(n<sup>2</sup>)|O(2<sup>n</sup>)|
|---|---|---|---|---|---|---|
|10|1|3.3|10|33.2|100|1,024|
|100|1|6.6|100|664.4|10,000|10<sup>30</sup>|
|1000|1|9.9|1000|9,966|1,000,000|사실상 계산 불가|

#### 시간 복잡도 구하는 규칙
+ 코드를 위에서부터 읽으며 연산 횟수를 세고 마지막에 제일 큰 항만 남긴다
    - 순차 실행은 `더한다` → O(n) + O(n) = O(2n) = O(n)
    - 중첩 반복은 `곱한다` → O(n) × O(n) = O(n<sup>2</sup>)
    - 남는 건 최고차항 하나 → O(n<sup>2</sup> + n) = O(n<sup>2</sup>)

    ```java
    for (int i = 0; i < n; i++) { }          // O(n)

    for (int i = 0; i < n; i++)              // 바깥 n번
        for (int j = 0; j < n; j++) { }      // 안쪽 n번 → O(n²)

    for (int i = 1; i < n; i *= 2) { }       // 1, 2, 4, 8... → O(log n)
    ```

+ 반복 변수가 `더해지며` 늘어나는지 `곱해지며` 늘어나는지가 n과 log n을 가른다
    - `i++` : 한 번에 1씩 → n번 반복 (O(n))
    - `i *= 2` : 한 번에 2배씩 → log<sub>2</sub>(n)번 반복 (O(log n))
+ 안쪽 반복이 `j < i`처럼 줄어들어도 결국 O(n<sup>2</sup>)
    - 총합이 n(n+1)/2 (가우스 공식) → 상수 1/2를 버리면 n<sup>2</sup>
+ 정렬이 O(n log n)인 이유도 같은 계산이다
    - 절반씩 쪼개니 깊이가 log n, 각 깊이마다 n개를 훑으니 n × log n
+ 재귀는 `호출 횟수 × 한 번의 비용`으로 센다
    - 피보나치 재귀는 호출마다 둘로 갈라지므로 호출 횟수가 2<sup>n</sup>

#### 상수가 버려지는 이유
+ 시간복잡도는 입력 n에 따라 성능이 어떻게 바뀌는지 보는 것
+ 이때 작은 수나 낮은 차수 항은 거의 영향이 없음
    - `T(n) = 3n² + 5n + 100`
    - n이 작을 땐 모두 영향받지만 n이 커질수록 `3n²`의 영향력이 커짐
    - 그래서 O(n<sup>2</sup>)로 표기

#### 최선 · 평균 · 최악
+ 같은 알고리즘도 `어떤 입력이 들어오느냐`에 따라 연산 횟수가 달라진다
    - 배열에서 특정 값 찾기 (선형 탐색)
        + 최선 : 첫 번째에서 바로 찾음 → 1번
        + 평균 : 중간쯤에서 찾음 → n/2번
        + 최악 : 끝까지 훑었는데 없음 → n번
+ 표기법은 `상한이냐 하한이냐`를 나타내는 별개의 축이다
    - 빅-오 (O) : 아무리 나빠도 이보다 느리지 않다 (상한)
    - 빅-오메가 (Ω) : 아무리 좋아도 이보다 빠르지 않다 (하한)
    - 빅-세타 (Θ) : 상한과 하한이 같다 (정확한 증가율)
+ 그래서 `빅-오 = 최악`은 엄밀히는 맞는 말이 아니다
    - 최선/평균/최악은 `어떤 입력이냐`의 문제
    - O / Ω / Θ 는 `그 경우의 증가율을 어느 쪽에서 감싸느냐`의 문제
    - 다만 실무에서는 최악의 경우를 빅-오로 말하는 게 관행이라 둘이 붙어 다닌다
+ 그럼에도 최악을 기준으로 삼는 이유
    - 성능을 `보장`하려면 제일 나쁜 경우를 견딜 수 있어야 하기 때문
+ 평균을 같이 봐야 하는 경우도 있다
    - `HashMap` 검색은 평균 O(1)이지만 해시 충돌이 한 버킷에 몰리면 최악 O(n)
        + 자바 8부터는 충돌이 심한 버킷을 트리로 바꿔 최악을 O(log n)으로 낮췄다
    - 최악만 보면 `HashMap`을 못 쓰게 되므로, 최악이 얼마나 드문지도 같이 본다

#### 분할 상환 분석 (Amortized)
+ 가끔 오래 걸리는 연산이 섞여 있어도 `전체 횟수로 나누면` 평균 비용이 작을 수 있다
+ `ArrayList`의 `add()`
    - 빈 공간이 있으면 그냥 넣으므로 O(1)
    - 꽉 차면 더 큰 배열을 새로 만들어 전부 복사하므로 O(n)
    - 하지만 용량을 1.5배로 늘리기 때문에 복사가 매번 일어나지 않는다

        ```
        용량 10 → 꽉 참 → 15로 확장 (복사 10번)
        11 ~ 15번째 추가는 복사 없이 O(1)

        용량이 커질수록 확장 간격도 같이 벌어진다
        → n번 추가하는 동안의 총 복사 비용이 O(n)
        ```

    - 한 번당으로 나누면 O(1) → 이걸 `분할 상환 O(1)`(amortized O(1))이라고 한다
+ 핵심은 최악이 O(n)이라는 게 아니라 **그 O(n)이 연속으로 나올 수 없다**는 점
+ `ArrayDeque`도 배열이 꽉 차면 2배로 늘리므로 같은 이유로 분할 상환 O(1)이다
    - [스택 · 큐 · 덱](../03-스택-큐-덱/스택-큐-덱.md)에서 모든 연산이 O(1)이라고 한 것도 이 의미

#### 입력 크기로 복잡도 역산하기
+ 문제에서 n의 범위를 주면 `어떤 복잡도까지 허용되는지`를 거꾸로 알 수 있다
+ 대략 `1초에 1억 번 연산`을 기준으로 잡는다

|n의 크기|허용되는 복잡도|대표적인 풀이|
|---|---|---|
|n ≤ 10|O(n!), O(2<sup>n</sup>)|모든 순열·부분집합 완전 탐색|
|n ≤ 1,000|O(n<sup>2</sup>)|이중 반복문|
|n ≤ 100,000|O(n log n)|정렬, 우선순위 큐|
|n ≤ 10,000,000|O(n)|한 번 훑기|
|n이 그 이상|O(log n), O(1)|이진 탐색, 수식으로 계산|

+ n이 100,000인데 이중 반복문을 짰다면 100억 번 → 시간 초과
    - 알고리즘을 바꾸거나 자료구조를 바꿔야 한다는 신호

#### 표기법만 믿으면 안 되는 경우
+ 복잡도는 `n이 충분히 클 때`의 이야기라 실제 실행 시간과 어긋날 수 있다
+ n이 작으면 상수가 큰 O(n log n)보다 O(n<sup>2</sup>)가 더 빠를 수 있다
    - 자바의 정렬도 구간이 작아지면 삽입 정렬로 처리한다
+ 같은 O(n)이라도 메모리 접근 방식에 따라 실측이 갈린다
    - `ArrayList` 순회 : 연속된 메모리라 캐시에 통째로 올라옴
    - `LinkedList` 순회 : 노드가 흩어져 있어 매번 메모리를 새로 읽어야 함
    - 둘 다 O(n)이지만 실제 속도는 몇 배씩 차이난다
+ 복잡도는 `후보를 거르는 기준`이고 최종 판단은 측정이다

### 공간 복잡도
+ 알고리즘이 실행될 때 필요한 메모리 사용량을 분석한 것
+ 입력 데이터 크기에 따라 얼마나 많은 추가 공간이 필요한지 계산
+ 두 가지로 나눠서 본다
    - 입력 공간 : 입력 데이터 자체가 차지하는 공간 (어차피 있어야 하는 몫)
    - 보조 공간 (Auxiliary Space) : 알고리즘이 추가로 만들어 쓰는 공간
    - 보통 공간 복잡도라고 하면 `보조 공간`을 말한다
+ 추가 공간을 거의 쓰지 않으면 제자리(in-place) 알고리즘이라고 한다
    - 배열 뒤집기를 새 배열에 담으면 O(n), 두 인덱스를 맞바꾸면 O(1)
+ 재귀 호출, 추가적인 배열 사용 등에 따라 공간 복잡도가 증가할 수 있음
    - 재귀는 호출이 쌓인 만큼 스택 프레임이 그대로 공간 비용이 된다

    ```java
    // 재귀 - 호출이 n번 쌓이므로 공간 O(n)
    int sum(int n) {
        if (n == 0) return 0;
        return n + sum(n - 1);
    }

    // 반복 - 변수 하나면 되므로 공간 O(1)
    int sum(int n) {
        int total = 0;
        for (int i = 1; i <= n; i++) total += i;
        return total;
    }
    ```

    - 시간 복잡도는 둘 다 O(n)이지만 공간 복잡도가 다르다
    - 재귀 깊이가 너무 깊어지면 `StackOverflowError`
+ 시간 복잡도만큼 공간도 제한적인 자원
    - CPU는 느려도 기다릴 수 있지만 메모리는 부족하면 `그대로 종료` (`OutOfMemoryError`)

#### 시공간 트레이드 오프
+ 속도를 아끼기 위해 공간을 쓰기도 하고 공간을 아끼기 위해 속도를 포기하기도 함
+ 공간을 써서 시간을 버는 쪽
    - 메모이제이션 : 피보나치 재귀 O(2<sup>n</sup>) → 계산 결과를 배열에 저장하면 시간 O(n), 공간 O(n)
    - 해시 테이블 : 버킷 배열이라는 공간을 내주고 검색을 평균 O(1)로 만듦
    - 인덱스 : 원본 외에 색인을 따로 두고 조회 속도를 벌어옴
+ 시간을 내주고 공간을 버는 쪽
    - 제자리 정렬 : 추가 배열 없이 정렬하지만 비교·교환 횟수가 늘어남
    - 압축 : 저장 공간은 줄지만 읽을 때마다 풀어야 함
+ 어느 쪽을 택할지는 `무엇이 먼저 터지는가`로 정한다

|구분|시간 복잡도|공간 복잡도|
|---|---|---|
|의미|연산 횟수|메모리 사용량|
|보는 값|입력이 커질 때의 증가율|추가로 쓰는 보조 공간|
|줄이기 전략|연산 최적화, 반복문 개선, 자료구조 교체|중복 데이터 제거, 제자리 처리|
|한계를 넘으면|시간 초과 (느려짐)|메모리 초과 에러 (강제 종료)|
