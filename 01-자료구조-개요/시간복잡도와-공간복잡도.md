## 시간복잡도와 공간복잡도

복잡도는 코드가 **몇 초 걸리는지**가 아니라 **입력이 커질 때 얼마나 빨리 나빠지는지**를 재는 자다.
그래서 상수와 낮은 차수 항은 버리고, 최악의 경우만 남긴다.
[자료구조란](자료구조란.md)에서 나눈 자료구조들을 고를 때 실제 판단 기준이 되는 값이다.

### 시간 복잡도
+ 알고리즘이 실행되는데 걸리는 시간을 입력 크기(n)에 따라 분석한 것
    - n이 커질수록 연산 횟수가 얼마나 늘어나는가
    - 간단한 판단 기준
        + 고정된 횟수로 끝나는가 > O(1)
        + n에 비례해서 늘어나는가 > O(n)
        + n<sup>2</sup>에 비례해서 늘어나는가 > O(n<sup>2</sup>)
            ```
            // ArrayList 앞에서 제거
            [1][2][3][4][5]  → 요소 5개, 이동 4번
            [1][2]...[100]   → 요소 100개, 이동 99번

            n이 커질수록 이동 횟수도 같이 커진다
            → O(n) ✅

            // ArrayDeque 앞에서 제거
            head 포인터 하나만 이동
            요소가 5개든 100개든 딱 1번
            → O(1) ✅
            ```
+ 입력이 커질수록 얼마나 더 느려지는지 예측할 수 있게 도와줌

#### 빅-오 표기법 (Big-O)
+ 최악의 경우를 기준으로 연산 횟수를 표현
+ 안전한 성능 보장이 필요하기 때문에 최악을 기준으로 연산 횟수를 표현
    - O(1)
        + 상수 시간
        + 배열에서 인덱스로 접근
    - O(log n)
        + 로그 시간
        + 이진 탐색
        + 로그 log<sub>2</sub>(n)
    - O(n)
        + 선형 시간
        + 배열에서 특정 원소 찾기
    - O(n log n)
        + 로그 선형 시간
        + 퀵 정렬, 병합 정렬
        + O(n) 반복 * log<sub>2</sub>
    - O(n<sup>2</sup>)
        + 이차 시간
        + 버블 정렬, 선택 정렬
        + n(n+1)/2 (가우스 공식)
    - O(2<sup>n</sup>)
        + 지수 시간
        + 피보나치 수열의 재귀적 계산

|입력 크기(n)|O(1)|O(log n)|O(n)|O(n log n)|O(n<sup>2</sup>)|
|---|---|---|---|---|---|
|10|1|3.3|10|33.2|100|
|100|1|6.6|100|664.4|10000|
|1000|1|9.9|1000|9966|1000000|

#### 상수가 버려지는 이유
+ 시간복잡도는 입력 n에 따라 성능이 어떻게 바뀌는지 보는 것
+ 이때 작은 수나 낮은 차수 항은 거의 영향이 없음
    - `T(n) = 3n² + 5n + 100`
    - n이 작을 땐 모두 영향받지만 n이 커질수록 `3n²`의 영향력이 커짐
    - 그래서 O(n<sup>2</sup>)로 표기

### 공간 복잡도
+ 알고리즘이 실행될 때 필요한 메모리 사용량을 분석한 것
+ 입력 데이터 크기에 따라 얼마나 많은 추가 공간이 필요한지 계산
+ 재귀 호출, 추가적인 배열 사용 등에 따라 공간 복잡도가 증가할 수 있음
+ 시간 복잡도만큼 공간도 제한적인 자원
    - CPU는 느려도 기다릴 수 있지만 메모리는 부족하면 `그대로 종료`
+ 시공간 트레이드 오프
    - 속도를 아끼기 위해 공간을 쓰기도 하고 공간을 아끼기 위해 속도를 포기하기도 함

|구분|시간 복잡도|공간 복잡도|
|---|---|---|
|의미|연산 횟수|메모리 사용량|
|줄이기 전략|연산 최적화, 반복문 개선|중복 데이터 제거|
|충돌 가능성|느려짐|메모리 초과 에러|
