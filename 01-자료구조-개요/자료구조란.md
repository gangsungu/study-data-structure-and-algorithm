## 자료구조란

자료구조는 **데이터를 어떤 모양으로 담을지** 정하는 일이다.  
같은 데이터라도 어디에 담느냐에 따라 검색·삽입·삭제의 비용이 달라지고, 그 비용이 곧 알고리즘의 성능이 된다.  
여기서는 자료구조를 선형·비선형으로 나눠 전체 지도를 그리고, **그 비용을 재는 방법**은 [시간복잡도와 공간복잡도](시간복잡도와-공간복잡도.md)에서 다룬다.

### 자료구조 개요
+ 자료구조란 데이터를 효율적으로 저장하고 관리하는 방법을 의미
+ 효율적인 자료구조를 사용하면 데이터를 빠르게 검색, 삽입, 삭제할 수 있으며 알고리즘의 성능을 크게 향상시킬 수 있음
+ 자료구조는 `규칙`과 `구현`을 나눠서 본다
    - 추상 자료형 (ADT, Abstract Data Type)
        + 어떤 연산을 제공하는지만 정한 것 (무엇을 할 수 있는가)
        + 스택은 `맨 위에서만 넣고 뺀다`는 규칙일 뿐 내부를 배열로 만들지 노드로 만들지는 정하지 않는다
    - 구현 (Implementation)
        + 그 규칙을 실제로 어떤 메모리 구조로 만들지 (어떻게 할 것인가)
        + 같은 스택이라도 배열로도, 연결 리스트로도 만들 수 있고 성능이 달라진다
    - 자바의 `Deque`(인터페이스) ↔ `ArrayDeque`(구현체) 관계가 그대로 이 구분이다
+ 그래서 자료구조 선택은 `어떤 연산이 자주 일어나는가`를 먼저 정하고 그에 맞는 구현을 고르는 순서로 한다

### 분류 기준
+ 선형과 비선형을 가르는 건 `저장 위치`가 아니라 `요소끼리의 연결 관계`
    - 선형 : 요소 하나가 앞뒤로 하나씩만 연결 (1 : 1)
    - 비선형 : 요소 하나가 여러 요소와 연결 (1 : N, N : N)
+ 메모리에 연속으로 붙어 있는지(물리적 순서)와 순서가 하나로 이어지는지(논리적 순서)는 별개다
    - `LinkedList`는 메모리에 흩어져 저장되지만 순서가 하나로 이어지므로 선형이다

    ```
    // 선형 - 다음 요소가 항상 하나
    [1] → [2] → [3] → [4]

    // 비선형 - 다음 요소가 여럿
        [1]
       ↙   ↘
     [2]   [3]
    ```

### 선형 자료구조
+ 데이터가 `순차적`으로 저장되는 구조로 인접한 데이터끼리 연결됨
    - 배열 (Array)
        + 같은 자료형의 데이터를 연속된 메모리에 저장
    - 리스트 (List)
        + 순차적으로 데이터를 저장하지만 동적으로 크기를 조절할 수 있음
        + `ArrayList`, `LinkedList`
    - 스택 (Stack)
        + 후입선출
    - 큐 (Queue)
        + 선입선출
    - 데크 (Deque)
        + 양쪽에서 삽입과 삭제가 가능한 자료구조
        + 양 끝이 모두 O(1)이라 슬라이딩 윈도우, 회문 검사처럼 **양 끝을 동시에 다루는 문제**에 쓴다

### 비선형 자료구조
+ 데이터가 `계층적이거나 복잡한 관계`를 가지며 하나의 순서로 이어지지 않음
    - 해시 테이블 (Hash Table)
        + 키-값 형태로 데이터를 저장하고 해시 함수를 이용해 빠르게 검색이 가능
    - 그래프 (Graph)
        + 정점(Vertex)와 간선(Edge)로 구성되며 복잡한 관계를 표현하는데 사용
    - 트리 (Tree)
        + 부모-자식 관계를 가지는 계층적 자료구조
        + 사이클이 없는 그래프의 한 종류
        + 이진트리, 이진탐색트리
    - 힙 (Heap)
        + 특정한 순서를 유지하는 트리 기반의 자료구조
        + 최소힙, 최대힙, 우선순위 큐
    - 집합 (Set)
        + 중복을 허용하지 않고 순서를 보장하지 않는 자료구조
        + 그 자체는 규칙(ADT)이고 실제 구현은 해시 테이블(`HashSet`) 또는 트리(`TreeSet`)

### 자료구조 고르는 기준
+ 순서가 의미 있는가 → 선형 / 관계나 계층이 있는가 → 비선형
+ 인덱스로 바로 꺼내야 하는가 → 배열, `ArrayList`
+ 중간 삽입·삭제가 잦은가 → 연결 리스트
+ 넣고 빼는 위치가 양 끝으로 정해져 있는가 → 스택 · 큐 · 덱
+ 키로 찾는가 → 해시 테이블
+ 항상 최댓값이나 최솟값만 필요한가 → 힙
+ 중복을 걸러야 하는가 → 집합
+ 정렬된 상태를 유지해야 하는가 → 트리
